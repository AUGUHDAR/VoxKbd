# Vox Kbd 版本兼容核查（1.0.2）

核查日期：2026-09-27。
方法：每个 MC 版本的 Mojang 官方映射文件（`client.txt`，ProGuard 格式、含完整方法签名）逐版本解析，26.x 用本地映射 jar `javap` 反查；再用 MCP 搜索（yarn javadoc、NeoForged/Fabric 文档、社区 mod）交叉验证断代点。编译通过不等于 mixin 注入成功——mixin 签名必须与目标版本的运行时方法签名逐字匹配，本文就是这份对照账。

## 二、本轮修复（都有上表证据支撑）

1. **HUD mixin 签名错配（18 树）**——编译期不报错、运行时静默失效（`require=0`）：
   - 1.20/1.20.1/1.20.2–1.20.6 七树：handler 补 `float partialTick`；
   - 1.21 系十一树（forge/neoforge 全部 + fabric 的 1.21.6 之后）：handler 补 `DeltaTracker`；
   - 1.21.1 实锤在先：玩家日志 `Expected (class_332, class_9779, CallbackInfo)`。
2. **forge/neoforge 缺安卓桥（17 树，1.20–26.2）**：桥类（GlfwKeyMap/VoxKbdMixinApi/FclInputInjector/PlatformBridge）与 `VoxKbdKeyCallbackMixin` 只在 Fabric 树里，Forge/NeoForge 玩家在 FCL/ZL2 上整个翻译管线是死的。已按族从 Fabric 兄弟树复制并注册进 `voxkbd.mixins.json`。
3. Forge 1.20.1 SRG 运行时：确认 jar 内 `voxkbd.refmap.json` 存在且 `mixins.json` 已引用（本来就对）；NeoForge 全系官方名运行时、刻意无 refmap（本来就对）。

## 三、逐树验证结果（1.0.2 jar 实测反编译比对）

28 树全部通过：HUD handler 参数与该版本 `render`/`extractRenderState` 签名一致；forge/neoforge 桥类齐全；26.3 三树为新式 `keyPress` 拦截桥；pack.mcmeta、更新检测、五重安卓判定全部在包内。

## 四、遗留风险（诚实记录）

- `VoxKbdMixinApi`（安卓桥）用 `KeycodeTable.defaults()`，而 `ModRuntime` 给桌面路径装的是配置表；玩家若改过 base/stride，安卓合成键会与绑定显示错位。1.21+/26.3 桥已改读 `GlfwDeliverer.table()`，1.20 桥仍是 defaults——影响面：改过键码表配置的安卓玩家。
- 1.21.9 `setupKeyboardCallbacks(Window,…)` 内部调用点存在性是从字节码常量池确认的，没跑过真机；26.1/26.2 同。
- Forge 1.20.1 的 `@Redirect(remap=false)` 打在 `glfwSetKeyCallback` 上，SRG 环境下 LWJGL 调用点不受重映射影响，理论成立，真机待验证。
